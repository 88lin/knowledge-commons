# 知识公社 · 学习系统设计

> 2026-10-14 立。本文记录**为什么这样设计**，以及每一条机制的出处与落地状态。
> 结论来源：对 30+ 个真实学习平台的机制调研（freeCodeCamp / Exercism / CS50 / The Odin Project / roadmap.sh / LeetCode / Boot.dev / Scrimba / Kaggle Learn / Khan Academy / Anki·FSRS / Duolingo / Quizlet / Memrise / Brilliant / edX / Coursera / 蓝桥云课 / 极客时间 / 华为·阿里云认证 / Codeforces / AtCoder / 洛谷 / WorldSkills 竞赛规则）。

---

## 一、诊断：原来坏在哪

站内早已有学习引擎 `learn/kc-learn.js`（进度条 / 标记学完 / 小测 / 下一讲 / 继续学习），但：

| 病症 | 证据 |
|---|---|
| 引擎只焊了一半 | `cloud.html` 接了 7 讲；`courses.html` 挂了引擎 0 讲；`beginner.html`(19.5KB)、`skills.html`(21.5KB) 完全没接 |
| 只有「学过没学过」，没有「记住没有」 | 无错题回流、无复习排期、无掌握度 |
| 内容跳转无闭环 | 大量课程页是「导读 + `study.html#d=…` 外链」，学习者被弹走 |
| 首页是资料目录，不是学习入口 | 打开看到的是一屏卡片，而不是「今天该学什么」 |
| 未完成即负债 | 只有「完成/未完成」两态，没学完的永远挂着，弃坑率高 |

**核心判断：不是内容不够，是闭环缺失。** 收集侧已经很重（1900+ 文件 / 620MB），缺的是「学 → 练 → 反馈 → 复习 → 掌握」。

## 二、已落地（有实测证据）

| 机制 | 实现 | 出处依据 |
|---|---|---|
| **错题本** | 任意页 `.qz` 答错自动入库（题面/选项/解析/来源页） | 各平台共性缺口，自建站最易差异化 |
| **间隔重复（FSRS-lite）** | D/S/R 三变量 + 目标保持率 90%，`F=19/81, DECAY=-0.5` | Anki 现役算法（FSRS）；Anki 官方默认 90%，「高于 90% 负荷陡增」 |
| **答错不清零** | 答错 → `S×0.2`、10 分钟后再来 | 修 SM-2「失败即打回 1 天」的过度惩罚 |
| **四级掌握度** | 未学 / 学过 / 熟练 / 精通 | Khan Academy 四级模型 |
| **混测才能升「精通」** | 练习答对封顶「熟练」；随机混测答对才升「精通」 | Khan 核心洞察：**隔离练习 ≠ 可迁移掌握** |
| **混测模式** | 跨页随机抽 10 题 | 交错练习优于分块（Rohrer & Taylor 2007） |
| **每日上限 20 题** | 防复习队列雪崩 | Quizlet 的 New cards per day |
| **每日目标 + 连击 + 护身符 ×2** | 达标记连击；断签消耗护身符；文案去羞耻化 | Duolingo 官方：冻结券使 DAU +0.38%；官方自认断签「反而非常泄气」 |
| **三态进度单元** | 学习中 / 已学完 / **跳过** | roadmap.sh 三态（含 skipped）、Kaggle 允许跳过——**降低未完成负债感** |
| **数据可迁移** | 一键导出/导入 JSON | 无后端站结构性限制的兜底 |
| **学后立即测** | 每节末尾 1 题小测 + 解析 | 检索练习 > 重复阅读（Roediger & Karpicke 2006） |

**实测记录**：答对一题 → `{m:2（熟练）, S:1.8, D:5, 下次 2 天后}`；三态循环 `doing → done → skip → 空` 逐步持久化正确。

## 三、待落地（按优先级）

| 优先 | 机制 | 为什么 | 成本 |
|---|---|---|---|
| P0 | **权重表 + 覆盖率仪表盘** | 「学什么、学到什么程度算够」——华为 HCIA 大纲给章节占比 + 通过线 600/1000；阿里云 ACP 100 分 / 80 过；世赛 WSOS 权重表本库已有 | 中（需整理权重数据） |
| P0 | **限时模拟器** | 决定「练得怎么样」。固定开赛时间 + 倒计时 + 提交序列 + 赛后报告（时间 / 决策 / 错误 / 资产 / 目标）。世赛 4 天逐日评分、**日清是制度不是自律** | 中 |
| P1 | **验收清单 + 产出物** | 没有产出物的知识点不算「可训练」。用「命令输出 / 配置截图 / 部署产物 / 3 分钟口述」代替自动判题（云计算的判题没法在浏览器里跑） | 低 |
| P1 | **把引擎铺到全站课程页** | 目前只有 3 个页面接了 `.lesson` / `.qz` | 低（机械活，可批量） |
| P2 | **单元切到 5–8 分钟** | edX 实证：中位参与时长 ≤6 分钟，与总长无关（Guo, LAM 2014） | 高（内容重构） |
| P2 | **软截止 + 自动重置** | Coursera：硬 deadline 提完成率但制造流失；正解是软截止、错过不扣分 | 低 |
| P3 | 证书 + 进度快照哈希 | 无后端站证书无公信力；可内嵌进度 JSON 的 SHA-256 供第三方核验 | 中 |

## 四、反模式清单（明确不做）

1. 按「看完」计进度 → 按达标技能数计
2. 一次遗忘就清零 → 用回退惩罚（已改）
3. 硬 deadline 无救济 → 软截止 + 自动重置
4. 测评只当裁判 → 失败必须触发补练
5. 复习队列无上限 → 必设每日上限（已设 20）
6. 只教不测 / 只测不教 → 微单元内嵌题 + 单元末混测并存
7. streak 无逃生舱 → 护身符 / 周目标替代（已设 2 张）
8. 单节太长 → 硬约束 <8 分钟
9. 只有一种模态 → 可听内容提供音频版
10. 不给收工信号 → 队列清空即明确结束（已做）
11. **公开排行榜** → Advent of Code 作者 2024 年删掉全球榜：带来巨大压力、有人 DDoS。**只做私有小圈子榜，或不做**

## 五、工程注意（踩过的坑）

- **静态资源缓存**：GitHub Pages + WebView 会长期缓存同名文件，**改了 `kc-learn.js` 但页面引用同名 → 用户永远拿旧版**。解法：引用带版本号 `kc-learn.js?v=2`，每次改动 bump。`kc-srs.js`、`style.css`、`sw.js` 同理。
- **Service Worker**：再叠一层缓存，改动后需更新 `sw.js` 的版本号才会刷新。
- **判题沙箱**（若将来做前端判题）：`iframe sandbox="allow-scripts"` 且**不加** `allow-same-origin`；`new Function` 跑用户代码必须配 Web Worker + `terminate()` 超时。
- **数据兜底**：localStorage 约 5–10MB 且可能被清；进度必须能导出 JSON。

## 六、引擎接口约定（写课程页时照这个来）

```html
<script defer src="kc-learn.js?v=2"></script>   <!-- 进度 + 小测 -->
<script defer src="kc-srs.js?v=2"></script>     <!-- 错题本 + 复习 + 掌握度 -->

<div id="kc-review"></div>   <!-- 入口页放这个 → 出现「今天的学习任务」卡 -->

<section class="card">
  <div class="lesson" id="sec1">              <!-- 一个进度单元 -->
    <h2>标题</h2>
    …正文…
    <div class="qz">                          <!-- 小测 -->
      <div class="qz-q">题面</div>
      <button class="qz-o" data-a="0">错项</button>
      <button class="qz-o" data-a="1">正确项</button>   <!-- data-a="1" = 正确答案 -->
      <div class="qz-why" hidden>解析</div>
    </div>
  </div>
</section>
```

`#kc-resume`（入口页的「继续学习」卡）由 `kc-learn.js` 负责，`#kc-review`（今日任务）由 `kc-srs.js` 负责，两者可同页共存。
